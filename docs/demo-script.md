# 演示脚本

> AI 生成草稿，对外展示前需由 Digi 工程师审核。每个场景标注所需最少设备；第一步环境是 **1 台 Hub（hub-a）+ 1 台 VM（vm-win-1）**。

**演示前准备**

- 服务器：`python -m server`，浏览器打开 `https://10.70.1.63:8443`（自签证书，浏览器会提示，演示环境可继续；生产需受信证书）。
- 登录：用户名 `admin`，密码为 `.env` 的 `CONSOLE_ADMIN_PASSWORD`。
- 演示设备：hub-a 端口 6 = U 盘（映射为 E:），端口 3 = Digi XBee 开发板。
- 没有真实设备、想排练页面：`PYTHONPATH=. python scripts/dev_console.py`，打开 `http://127.0.0.1:8470`，登录 `admin / demo`（全是 mock，不碰真实 Hub 和配置）。
- 想让 vm-win-1 起代理：见 `docs/agent-windows-steps.md`。

---

## 1. 控制台显示 8 个端口与 vm-win-1 在线【1 Hub + 1 VM】

1. 登录后进入「端口总览」：hub-a 一个面板，8 张端口卡片，每张带颜色**和文字**状态（空闲 / 已分配 / 已连接 / 故障）。
2. 右侧「在线代理」列表里 vm-win-1 前面是绿点。页头"实时"徽章亮着，表示 WebSocket 推送在工作。
3. 「代理」页：vm-win-1 的 Manager 模式为 `service`，自检显示"正常"。

**讲解点**：卡片按 Hub 分组，Hub 数量变化时页面自动适应；Hub 离线只影响它自己的卡片。

## 2. 用向导为 hub-a 做分组和 Client ID 配置【1 + 1】

1. 「Hub 管理」→ hub-a 行点「编辑」→ 直接从第 2 步开始：只读探测并**自动备份**，页面显示现有分组与客户端。
2. 第 3 步：选"每口一组"，给端口 6 起显示名"演示 U 盘"，端口 3 起"XBee 板"。下方"与当前配置的差异"列出将新增/修改的项。
3. 第 4 步：勾选 vm-win-1 上报的 Client ID，授权模式选**动态分配（推荐）**：只加入客户端列表，不预先授权。
4. 第 5 步：核对变更清单，勾选确认后点「确认并应用」。进度逐项变绿；成功后提示已写入 `config.yaml`（旧文件备份在 `backups/`）并热加载。

**讲解点**：第 5 步确认之前对 Hub 零写入；任一步失败立即停止，可一键恢复到第 2 步的备份。

## 3. vm-win-1 申请端口 6 → 自动授权并连接【1 + 1】

1. 在 VM 上：`agent.exe ui` → 选 2（申请）→ 输入 `演示 U 盘`（或 `hub-a-p06`）。
2. 控制台端口 6 的卡片变为 **已连接**，显示持有者与租约倒计时。
3. VM 设备管理器出现 USB 磁盘，资源管理器里出现 E:。

**讲解点**：流程是 服务器授权（Hub REST）→ 下发 CONNECT → 代理调用 Manager 连接 → ACK → 已连接。

## 4. 第二个客户端申请同一 UKey → 让出【第一步用模拟代理】

第一步只有一台 VM，用 Ubuntu 上的模拟代理充当第二个客户端：

```bash
# 配置 agent/agent.yaml（server_url/api_url 指向服务器，server_ca_cert 指向 certs/server.crt，enrollment_token 填 .env 的值，hostname: mock-vm-2）
python agent/agent.py --config agent/agent.yaml --mock-manager
```

1. 控制台「代理」页批准 `mock-vm-2`。
2. 在模拟代理的本机菜单（`python agent/agent.py ui --config agent/agent.yaml`）申请端口 6。
3. vm-win-1 的代理收到 RELEASE_ASK 并同意 → 端口 6 转给 mock-vm-2（卡片持有者变化；vm-win-1 的 E: 消失）。
4. 把 vm-win-1 代理配置里的 `release_policy` 改为 `deny` 再重复：申请方得到 busy，端口不变。

**注意**：模拟代理申请端口时，调度器仍会在真实 Hub 的客户端列表里加入一个 `ukey-mock-vm-2` 条目并授权；演示后可在「Hub 管理 → 编辑」里清理。
**真实演示**需要 2 台 VM，第二步扩容时重跑，无需改代码。

## 5. 控制台强制回收【1 + 1】

1. 端口 6 已连接时，点卡片上的「强制回收」→ 确认对话框提示"会强制断开设备"。
2. 卡片回到空闲；VM 上 E: 消失；Hub 的客户端授权被撤销。

**讲解点（实测）**：Hub 撤销授权会**立即**强制断开 VM 上的设备（同一秒），所以正常释放先让代理 DISCONNECT（优雅），再撤销授权。强制回收也是先试优雅断开，失败才直接撤销。

## 6. 停止代理服务（模拟崩溃）→ 自动回收【1 + 1】

1. 端口 6 已连接。在 VM 上：`Stop-Service UKeyAgent`（或结束进程）。
2. 控制台里 vm-win-1 变灰（离线）；约 `heartbeat_timeout_seconds`（45 秒）后，端口 6 自动回到空闲。
3. 审计日志出现 `agent_timeout` 与 `release (agent_lost)`。

**讲解点**：兜底不依赖代理——服务器直接通过 Hub API 撤销授权。租约（默认 10 分钟）到期而代理不响应时同理。

## 7. 审计日志【1 + 1】

「审计日志」页：时间、操作者、代理、端口、动作、结果、详情；可按端口 / 代理 / 动作过滤。能看到上面每一步：登录、授权、连接、让出、强制回收、心跳超时、向导的探测与应用。

## 8. 向导添加第二台 Hub；一台断电【2 Hub】

1. 「Hub 管理」→「添加 Hub」：名称自动建议 `hub-b`，填 IP、管理员用户名、密码（提交后不回显）。
2. 第 2 步探测 → 第 3 步每口一组（24 口 Hub 会生成 24 个分组）→ 第 4 步选 Client ID → 第 5 步应用。
3. 完成后「端口总览」多出 hub-b 面板，**无需重启、无需改代码**；在线代理会收到新的 CONFIG。
4. 给 hub-b 断电：一个健康检查周期内（约 15 秒，取决于超时）hub-b 所有卡片变 **故障**，hub-a 不受影响，仍可申请端口。上电后自动恢复（有租约且授权仍在的端口恢复为已连接）。
5. 「移除 Hub」：只从服务器配置里删除，不改动 Hub 上的配置；有活动租约时按钮会被拒绝。

**没有第二台 Hub 时**：用 `scripts/dev_console.py`，向导里添加 `10.70.1.209` / 密码 `hubb`（mock 的 24 口 Hub）可演示向导全流程。dev_console 里没有"断电"开关；Hub 离线的行为由自动化测试（`tests/test_scheduler.py`）覆盖，真实演示需要第二台 Hub。
